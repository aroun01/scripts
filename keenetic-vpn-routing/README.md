# Исключения из VPN на Keenetic

Эта инструкция помогает настроить выход устройств через AmneziaWG, направляя IPv4-трафик к подсетям из списка напрямую через интернет-провайдера. Список содержит российские сервисы, включая банки, Госуслуги и MAX. Остальной IPv4-трафик устройств выбранной VPN-политики должен идти через VPN.

В проекте два файла: `amnezia-add-routes.sh` — скрипт оболочки, а `amnezia-routes.txt` — список сетей. Python для них не нужен. Схема проверена на конкретном Keenetic с Entware; названия меню, интерфейсы и номера таблиц на других устройствах могут отличаться. Перед настройкой сохраните резервную копию конфигурации Keenetic через веб-интерфейс.

## 1. Подключите AmneziaWG

1. Убедитесь, что версия KeeneticOS и установленный компонент WireGuard поддерживают версию AmneziaWG вашего VPN. Подготовьте отдельный конфигурационный файл AmneziaWG в оригинальном формате `.conf`.
2. В веб-интерфейсе откройте **Интернет → Другие подключения → WireGuard**, нажмите **Загрузить из файла** и выберите конфигурацию.
3. Откройте настройки созданного подключения, включите **Использовать для выхода в интернет**, сохраните и включите подключение. Убедитесь, что оно работает.
4. В разделе **Приоритеты подключений** создайте политику доступа через это VPN-подключение и назначьте её нужным зарегистрированным устройствам или сегменту сети. Проверьте приоритеты и резервные подключения: если в политике разрешён переход к провайдеру при отключении VPN, остальной трафик тоже может пойти напрямую. До добавления исключений проверьте на выбранном устройстве, что сайт проверки IP показывает адрес VPN.

Пункты меню зависят от версии KeeneticOS. См. [инструкцию Amnezia для KeeneticOS 4.2 и AmneziaWG 1.0](https://docs.amnezia.org/ru/documentation/instructions/old-keenetic-os-awg/); для других версий используйте инструкцию к своей версии. Одна только галочка «Использовать для выхода в интернет» не назначает политику устройствам.

## 2. Установите Entware и подключитесь по SSH

Установите компонент OPKG и Entware по [инструкции Keenetic](https://help.keenetic.com/hc/en-us/articles/360021214160). Нужен поддерживаемый роутер и настроенное постоянное хранилище для `/opt`. Настройте SSH-сервер Entware и подключитесь к его Linux-оболочке с правами root. Это не обязательно тот же SSH-порт, что у командной строки Keenetic: используйте порт и учётные данные, заданные при установке Entware.

Ниже команды выполняются **в оболочке Entware**, не в CLI Keenetic и не в Python. Убедитесь, что доступны `ip`, `grep`, `tr` и `crontab`; при отсутствии нужных утилит установите соответствующие пакеты Entware. Команды маршрутизации требуют `ip` с поддержкой `rule` и таблиц маршрутизации.

## 3. Скопируйте файлы и сохраните прежние версии

Скопируйте оба файла проекта в `/opt/etc/` через SCP или другим доступным способом. Например, находясь в папке проекта на компьютере, используйте (подставьте адрес роутера и SSH-порт Entware):

```sh
scp -O -P ПОРТ_ENTWARE amnezia-add-routes.sh amnezia-routes.txt root@АДРЕС_РОУТЕРА:/opt/etc/
```

Если файлы уже существуют, **перед копированием** сохраните их на роутере:

```sh
cp -p /opt/etc/amnezia-add-routes.sh /opt/etc/amnezia-add-routes.sh.bak
cp -p /opt/etc/amnezia-routes.txt /opt/etc/amnezia-routes.txt.bak
```

Команды резервного копирования нужны только для существующих файлов; используйте новые имена копий при повторной настройке. Параметр `-O` включает старый протокол SCP, который может понадобиться, если на роутере нет SFTP-сервера.

## 4. Найдите параметры своей сети

В оболочке Entware выполните:

```sh
ip -4 route show table main
ip -4 rule show
ip -4 route show table all
```

В основной таблице найдите маршрут провайдера `default via ШЛЮЗ dev ИНТЕРФЕЙС`. В `ip rule` найдите правило, которое соответствует метке выбранной VPN-политики, а в указанной им таблице — маршрут по умолчанию через VPN. Номер таблицы и метка зависят от конфигурации; **не считайте 4096 универсальным значением**. Если не удаётся однозначно связать политику, метку и таблицу, не применяйте скрипт до выяснения. В некоторых подключениях провайдера нет шлюза `via`; этот скрипт в текущем виде для них не подходит.

Откройте `/opt/etc/amnezia-add-routes.sh` в доступном текстовом редакторе и задайте в начале файла:

```sh
GW="IP_ШЛЮЗА_ПРОВАЙДЕРА"
IFACE="ИНТЕРФЕЙС_ПРОВАЙДЕРА"
TABLE="НОМЕР_ТАБЛИЦЫ_VPN_ПОЛИТИКИ"
```

Уберите текстовые заполнители и сохраните файл. `eth2.6` и `4096` в опубликованном примере относятся к конкретной настройке и могут не подойти. Значение `GW` намеренно оставлено заполнителем. Если шлюз или интерфейс меняются при переподключении, вручную обновите параметры и переустановите маршруты: скрипт не определяет новый шлюз автоматически и пропускает существующий маршрут, даже если у него устаревший шлюз.

## 5. Добавьте и проверьте маршруты

```sh
chmod +x /opt/etc/amnezia-add-routes.sh
mkdir -p /opt/var/log
sh -n /opt/etc/amnezia-add-routes.sh
/opt/etc/amnezia-add-routes.sh add
/opt/etc/amnezia-add-routes.sh check
tail -20 /opt/var/log/amnezia-routes.log
```

Проверьте, что ошибок добавления нет. `check` показывает только первые 50 маршрутов и общее число; он не проверяет, что маршрут использует правильный шлюз. Для диагностики конкретных адресов подставьте IP устройства, LAN-интерфейс и метку VPN-политики из вашей системы:

```sh
ip -4 route get IP_ИЗ_СПИСКА from IP_УСТРОЙСТВА iif LAN_ИНТЕРФЕЙС mark МЕТКА_ПОЛИТИКИ
ip -4 route get IP_ВНЕ_СПИСКА from IP_УСТРОЙСТВА iif LAN_ИНТЕРФЕЙС mark МЕТКА_ПОЛИТИКИ
```

Для первого адреса ожидается интерфейс провайдера, для второго — VPN. Это проверка выбора маршрута с вручную указанной меткой, а не доказательство, что реальному устройству назначена эта метка или что сервис работает. Дополнительно проверьте сайты и внешний IP на самом устройстве, а также поведение после перезапуска VPN и роутера. Если VPN недоступен, проверьте фактическую политику резервирования.

## 6. Восстановление маршрутов

Маршруты, добавленные командой `ip`, могут исчезать при перезагрузке и изменении подключений. Скрипт сам не настраивает автозапуск. После настройки Entware cron можно добавить через `crontab -e` строку:

```cron
0 * * * * /opt/etc/amnezia-add-routes.sh add
```

Это повторная проверка **раз в час**, а не немедленное восстановление после перезагрузки или переподключения. До следующего запуска исключения могут отсутствовать. Для немедленного восстановления нужен дополнительно настроенный обработчик событий подключения, подходящий для вашей версии KeeneticOS/Entware. Убедитесь, что служба cron запущена, `/opt` доступен и после перезагрузки маршруты действительно восстанавливаются. При изменении шлюза cron сам его не исправит.

Для удаления текущих маршрутов списка с указанными `GW`, `IFACE` и `TABLE` используйте `/opt/etc/amnezia-add-routes.sh del`. Перед заменой списка или изменением шлюза сохраните старые параметры и список: команда `del` работает только с текущими значениями и не удалит маршруты для записей, уже убранных из файла. Затем можно восстановить резервные копии.

## Ограничения и источник списка

Список содержит по одной IPv4-подсети CIDR на строку; строки с `#` и пустые строки игнорируются. Он дополнен [RU Direct ru-standard](https://github.com/kyoresuas/ru-direct), снимок от 1 ноября 2026 года. Точные дубли и сети, полностью покрытые более крупными сетями, удалены. Автоматического обновления списка нет.

Сети могут включать несколько сервисов: весь трафик к ним из выбранной политики пойдёт напрямую. IP-адреса и состав сервисов меняются; полный охват не гарантирован. IPv6 скриптом не обрабатывается, поэтому его маршрут нужно проверять отдельно. Прямой маршрут по IP не исправляет проблемы DNS, самого приложения или VPN-детектирования на устройстве. Проверяйте доступность конкретных сайтов и соответствие их адресов списку.
